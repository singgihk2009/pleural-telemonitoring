A fixed nurse/119 footer is present on every screen, including login, warning,
loading and placeholders. The emergency action asks confirmation and opens the
native dialer (`tel:119`), never places a call automatically. No test calls 119.
Nurse phone numbers are not available from an approved settings endpoint, so
contact information explains the limitation instead of inventing a number.

Visual styling intentionally adds a navy TeleNapas masthead, generous spacing,
rounded white cards and neutral blue actions. It preserves Indonesian labels,
ordering and one-task-per-screen structure. No pixel-perfect claim is made.
Unapproved clinical feedback colors and example patient data in the PDF are not
production UI. Clinical bands remain documented requirements only:
HIJAU 0–39, KUNING 40–69, MERAH 70–100, inclusive. Neither these bands nor the old
delta logic from page 9 are implemented in mobile code. Pages 10–15 are context;
alerts, response times, notifications, offline queues, exports and schema changes
are outside this PR.

## Authentication and privacy

Uses POST `/api/v1/auth/patient/login`, GET `/auth/me`, GET
`/participants/{own-id}`, and POST `/auth/logout`. Patient identity is verified
before entering the app. The existing server denies controls, revoked/inactive
credentials and unauthorized participants. No API, schema, clinical policy or
researcher/admin grant behavior is modified.

Only token and expiry are stored using Expo SecureStore (Android Keystore-backed
encryption). No PIN, study code, contact, clinical draft or acknowledgement is
persisted. SecureStore failure closes login and attempts token revocation; there
is no plaintext fallback. Restored sessions revalidate identity/profile online.
Expired/401/403 sessions clear local state and secure storage. Foregrounding
revalidates and timers enforce expiration. Foreground/retry restoration yields to
an in-flight login through token exchange, patient identity/profile verification
and SecureStore persistence. Logout, unmount or a newer login invalidates the old
operation; every issued but uncommitted token reaches a revocation attempt in
`finally`. SecureStore operations are serialized, including stale-write cleanup,
so an abandoned login cannot delete a newer saved session. Expiration is checked
again after persistence. Revocation cannot be guaranteed while the API is
unreachable; server-side token expiration remains the bound. Logout clears local state and requests
server revocation; offline failure explicitly warns that revocation is unconfirmed.
Secure-store deletion failure warns against sharing the device. Requests time out,
use no-store/omit cookies and expose no server error bodies. There is no logging
of credentials/patient data, analytics, ads, notifications, FCM or WhatsApp.

Set non-secret `EXPO_PUBLIC_API_BASE_URL` to the approved HTTPS API ending in
`/api/v1`. There is deliberately no production default. HTTP is accepted only in
`__DEV__` for loopback or Android host alias `10.0.2.2`; release requires HTTPS.
An emulator can use adb reverse for a loopback API. Do not put credentials in
Expo public configuration. Install using the pinned Node 24/pnpm toolchain:
`corepack pnpm install --frozen-lockfile`, then
`corepack pnpm --filter @pleural/mobile start`.

## Accessibility and verification boundaries

Every text style is at least 16sp and font scaling stays enabled without a
maximum multiplier. Buttons/back/checkbox/slider have at least 48dp interactive
height; button labels wrap and footers/tiles/options wrap. Noninteractive calendar
cells are smaller and are not touch targets. Main content scrolls independently
of the persistent safety footer and accounts for safe areas/keyboard. Native
roles/labels/disabled/checked states, live notices and explicit text avoid relying
on color. No default VAS is announced as a chosen score.

Automated tests verify navigation, login errors/throttling/offline failures,
secure persistence/failure, staff rejection, token revocation/recovery, day-31
navigation, explicit zero/100 VAS, disabled symptom submission and WIB date
boundaries (including Laravel's UTC-midnight date serialization).

SDK compatibility was resolved through `expo install` using the installed SDK 58
compatibility map (`EXPO_OFFLINE=1`) because the Expo API is restricted. Versioned
docs were read from the official Expo repository after docs.expo.dev returned
Forbidden: `docs/pages/versions/v58.0.0/sdk/securestore.mdx`, `sdk/slider.mdx`, and
`docs/pages/router/introduction.mdx`. Installed source/types were also inspected.
The VAS track/thumb use native React Native views for explicit empty state and
high contrast, with an adjustable accessibility role and one-millimetre actions.
The secure-store backup plugin requires a new standalone native build to take
effect; Expo Go tests cannot validate that generated release configuration.

JavaScript export does not establish APK compatibility, Android 7 support, native
APK size below 30MB, dialer behavior, TalkBack order or large-font layout. The
existing Expo 58/React Native platform minimum may exceed the old PDF's Android 7
proposal; do not lower SDK requirements without a separate compatibility review.
No production build, deployment or real patient dataset is involved.
