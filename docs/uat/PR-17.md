# PR-17 — UAT fungsional Daily Assessment TeleNapas

## Paket dan batas UAT

Gunakan [synthetic-uat-daily.json](../../apps/api/tests/Fixtures/synthetic-uat-daily.json).
Versi `SYNTHETIC-UAT-DAILY-V1` berisi pertanyaan bentuk wajib dan huruf opsional,
dengan label sintetis yang tampil langsung di Android dan riwayat. Paket mengikuti
format review PR #15. Bagian `evidence` mendokumentasikan skenario pengujian ini.
`SYNTHETIC-UAT-TECHNICAL-ONLY` adalah penanda teknis tetap pada field API
`approval_reference`. Penanda tersebut tidak mewakili persetujuan penelitian.
Arsipkan paket beserta catatan UAT, tanpa kredensial atau data asli.

API hanya menerima dan mengaktifkan versi UAT ketika **semua** syarat terpenuhi:

- `APP_ENV=uat` dan `TELENAPAS_SYNTHETIC_UAT=true`.
- Koneksi aktif memakai MySQL dengan database persis `telenapas_synthetic_uat_test`.
- Versi memakai awalan `SYNTHETIC-UAT-`, referensi teknis cocok persis, dan semua
  kode pertanyaan memakai awalan `SYNTHETIC_UAT_`.

Di luar UAT, marker versi, referensi, atau kode pertanyaan yang dicadangkan
memblokir publikasi dan aktivasi. UAT pun menolak definisi penelitian biasa.
Paket kandidat [DO-NOT-PUBLISH PR #16](../research/pr16/daily-assessment.candidate.DO-NOT-PUBLISH.json)
tetap dalam status review penelitian.

## Penyiapan lingkungan terisolasi

1. Siapkan instance UAT tersendiri dengan API, dashboard, MySQL 8.4, volume, host,
   kunci Laravel, akun, dan kredensial khusus UAT. Batasi akses ke tim pengujian.
   Gunakan akses HTTPS privat yang didukung oleh APK pengujian. Pisahkan endpoint
   UAT dari endpoint yang dikenal APK penelitian.
2. Buat database **baru dan kosong** `telenapas_synthetic_uat_test` di instance
   MySQL UAT. Berikan akun runtime hanya hak pada schema itu. Gunakan identitas
   administrator terpisah untuk migrasi (termasuk trigger immutable) sesuai
   [panduan database](../database/README.md). Jangan arahkan kredensial atau
   layanan UAT ke `telenapas_demo` atau memulihkan dump penelitian ke sini.
3. Siapkan dependensi terkunci sesuai [README](../../README.md).
   Konfigurasikan proses API UAT dengan nilai berikut serta rahasia melalui
   pengaturan privat instance. Untuk Compose, gunakan override **di instance
   UAT** pada environment layanan API dan pada inisialisasi MySQL. Variabel
   environment eksplisit di Compose mengalahkan nilai file `.env` Laravel.

   ```dotenv
   APP_ENV=uat
   APP_DEBUG=false
   TELENAPAS_SYNTHETIC_UAT=true
   DB_CONNECTION=mysql
   DB_DATABASE=telenapas_synthetic_uat_test
   ```

   Atur `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, dan `APP_KEY`
   khusus UAT. Pada shell migrasi, cek host dan schema yang baru, lalu jalankan
   `php artisan migrate --force` menggunakan administrator UAT tanpa mengubah
   kredensial runtime. Jalankan `php artisan config:clear` dan restart layanan
   bila konfigurasi API berubah. Verifikasi `/up` dan `/api/v1/health` di UAT.
4. Atur `VITE_API_BASE_URL` untuk dashboard dan `EXPO_PUBLIC_API_BASE_URL`
   untuk APK pengujian ke API UAT (termasuk `/api/v1`). Bangun APK menurut
   [panduan APK](../mobile/APK-UAT.md). Untuk Vite lokal, pakai origin
   `http://localhost:5173` via tunnel privat bila perlu. Pertahankan allowlist
   origin yang ada. Jangan mengaktifkan tunnel publik atau CORS wildcard.
   Periksa URL tujuan kedua klien sebelum login.

## Penyiapan akun dan peserta

1. Provision satu akun staf fiktif aktif melalui konsol administrator UAT.
   Gunakan domain `example.invalid`, kata sandi unik dari pengelola rahasia,
   dan **hanya** role `PENELITI_UTAMA`. Contoh dari `apps/api`, dengan
   `UAT_RESEARCHER_PASSWORD` diberikan secara privat ke proses command:

   ```bash
   php artisan tinker --execute='
   if (!app()->environment("uat") ||
       config("assessment.synthetic_uat") !== true ||
       DB::connection()->getDatabaseName() !== "telenapas_synthetic_uat_test") {
       throw new RuntimeException("UAT configuration required.");
   }
   $password = getenv("UAT_RESEARCHER_PASSWORD");
   if (!$password) { throw new RuntimeException("Supply the UAT password securely."); }
   DB::transaction(function () use ($password) {
       $staff = App\Models\StaffUser::create([
           "nama" => "SYNTHETIC UAT RESEARCHER",
           "email" => "synthetic-uat-researcher@example.invalid",
           "password_hash" => $password,
           "status" => "AKTIF",
       ]);
       $staff->roles()->attach(App\Models\ResearchRole::firstOrCreate(["kode" => "PENELITI_UTAMA"]));
   });'
   ```

2. Login ke dashboard UAT. Daftarkan dua peserta aktif grup `INTERVENSI`,
   misalnya `SYN-UAT-ONLINE-01` dan `SYN-UAT-OFFLINE-01`, dengan tanggal pulang
   **kemarin menurut WIB** sehingga hari ini menjadi hari penelitian 1. Gunakan
   tanggal persetujuan formulir fiktif, versi `SYNTHETIC-UAT`, dan VAS baseline
   teknis yang dipilih eksplisit. Kosongkan kontak dan detail identitas opsional.
3. Terbitkan PIN Android melalui [alur dashboard yang ada](../enrollment/README.md#patient-android-pin-management-pr-10).
   Catat kode dan PIN hanya melalui kanal privat UAT. Masker semua kredensial
   pada tangkapan layar. Siapkan peserta terpisah karena hanya satu entri harian
   per peserta dan tanggal WIB yang dapat diterima.

## Publikasi manual

1. Buka **Review instrumen harian**. Pastikan daftar kosong dan versi aktif belum
   ada sebelum publikasi pertama. Verifikasi Android menampilkan asesmen belum
   tersedia pada status awal.
2. Tempel paket JSON, isi referensi `SYNTHETIC-UAT-TECHNICAL-ONLY`, dan pilih waktu
   berlaku di masa depan serta kedaluwarsa pada akhir jendela uji. Gunakan WIB.
   Sisakan cukup waktu untuk klik publikasi sebelum waktu efektif dan selesaikan
   pengujian offline sebelum kedaluwarsa atau pergantian tanggal.
3. Tinjau versi, jadwal, VAS, dan pemetaan kedua pertanyaan. Centang konfirmasi
   publikasi teknis dan klik **Publikasikan versi ini** satu kali. Cocokkan
   tanda terima dan daftar versi dengan versi, aktor, referensi, efektivitas,
   dan kedaluwarsa. Ikuti prosedur [PR #15](PR-15.md) bila respons hilang.
4. Verifikasi Android belum dapat mengisi sebelum waktu efektif, menampilkan
   pertanyaan sintetis ketika aktif, dan berhenti menawarkan pengiriman baru
   setelah kedaluwarsa. Verifikasi riwayat yang sudah tercatat tetap tersedia.
   Gunakan versi baru untuk perubahan; jangan edit baris publikasi.

## Skenario perangkat

| Langkah | Bukti yang dicatat |
|---|---|
| Login peserta online, buka **Isi Harian** setelah waktu efektif | Hari 1, versi publikasi, VAS kosong dan dua pertanyaan dari server |
| Pilih VAS 0, tinggalkan bentuk kosong, lanjutkan | Aplikasi menuntut jawaban wajib. Huruf opsional dapat dikosongkan |
| Pilih bentuk, tinjau, batal kembali, lalu konfirmasi dan kirim | Ringkasan pilihan dan VAS; satu tanda terima server dan satu baris riwayat |
| Login peserta offline, muat status saat online, matikan jaringan, isi VAS 100 dan pilihan, tinjau dan konfirmasi | Status antrean tertunda; keberhasilan baru muncul setelah tanda terima server |
| Tutup proses Android, buka kembali, autentikasi ulang sesuai UI, sambungkan jaringan sebelum batas | Antrean pulih untuk pemilik yang sama, tersinkron, dan menghasilkan satu tanda terima. Uji unit antrean memeriksa penyimpanan terenkripsi; tangkapan layar memverifikasi perilaku UI |
| Ulangi body dan UUID identik melalui API UAT memakai kredensial peserta yang sama, lalu uji payload berbeda dengan UUID itu | HTTP 200 dengan `replayed: true` dan tanda terima identik; perubahan body menghasilkan 409. Gunakan payload sintetis dari harness privat; jangan log token atau PIN |
| Buka detail peserta di dashboard peneliti, pilih riwayat asesmen, filter tanggal WIB dan tipe HARIAN | UUID, VAS, versi, dan label historis cocok; satu entri per peserta |
| Periksa audit read-only melalui akun berizin pada schema UAT | Satu `instrument.published` per versi, satu `assessment.submitted` per UUID, dan `privileged.access` untuk pembacaan peneliti. Cocokkan aktor/entitas dengan tanda terima |
| Setelah kedaluwarsa, buka ulang aplikasi dan riwayat | Pengiriman baru tertutup; riwayat tetap tersedia. Jumlah baris klasifikasi, peringatan, dan pengiriman notifikasi tetap nol |

Ambil tangkapan layar Android saat formulir, review, antrean, dan receipt,
serta dashboard pada receipt publikasi dan riwayat. Simpan bersama timestamp WIB,
versi APK, dan versi instrumen. Periksa tampilan terhadap panduan visual TeleNapas.
Alur Android existing dipakai tanpa perubahan layout pada PR ini.

## Perubahan dan kebutuhan deployment

- API memeriksa identitas UAT saat publikasi dan saat menentukan instrumen aktif.
  Otorisasi, validasi, transaksi publikasi, receipt immutable, idempotensi,
  provenance, dan audit menggunakan jalur existing.
- Dashboard memberi label teknis UAT pada review dan tanda terima. Paket JSON
  tersedia untuk review manual. Android tetap menggunakan kontrak API existing.
- Untuk uji fungsional baru, deploy revisi API dan dashboard setelah review ke
  instance UAT, lalu lakukan publikasi manual dari dashboard. Schema UAT kosong
  membutuhkan migrasi existing; PR ini tidak menambah migrasi atau seeder.
- Produksi dan penelitian tidak perlu flag UAT, perubahan data, atau konfigurasi
  UAT. Jangan promosikan volume, snapshot, dump, kunci atau akun dari UAT.
  Rilis dan merge merupakan keputusan terpisah.
