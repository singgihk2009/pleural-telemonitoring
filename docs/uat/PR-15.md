# PR15 — Review dan publikasi instrumen untuk UAT

Branch feature/pr-15-instrument-review-publication; base main b2737ca.
Tidak ada deployment/migration/seeder/perubahan konfigurasi lokal. Database

## Alur peneliti

Login staf existing → Review instrumen harian. GET existing /research/daily-instruments
harus mengizinkan peneliti sebelum editor dibuka. Wewenang server tetap Gate create
Participant: PENELITI_UTAMA aktif, deny assessor/admin/patient combinations existing.
Bukan sekadar menyembunyikan tombol. Pengguna lain tidak dapat POST lewat API.

Awal layar kosong dan **Menunggu kelengkapan/persetujuan**. Baca
[matriks](../research/instrument-traceability-pr15.md). Tidak ada delapan pertanyaan
PDF yang dipromosikan menjadi default. Isi paket JSON dari dokumen final yang
benar-benar ditinjau, nomor referensi persetujuan aktual, waktu efektif dan expiry
WIB. Review ringkasan, centang konfirmasi, lalu klik Publikasikan versi ini.
Opening/mount/migration tidak pernah POST. Waktu dikonversi WIB fixedUTC+7 ke UTC
millisecond Z; tidak tergantung timezone browser. Server tetap otoritatif.

Paket review lokal (sketsa **sengaja belum publishable**, bukan data pengganti):

```json
{
  "definition": {
    "version": "",
    "schedule": {"timezone":"Asia/Jakarta","first_day":null,"last_day":null,"late_policy":"same_day_only"},
    "questions": []
  },
  "evidence": {"instrument":"","vas":"","schedule":"","validation":"","questions":{}}
}
```

Isi definition.questions hanya setelah keputusan final, dengan struktur existing
`{code,label,required,options:[{value,label}]}`. Untuk tiap code, evidence.questions
wajib berisi `{definition: sitasi, required: sitasi, options: {VALUE: sitasi}}`.
Setiap sitasi perlu dokumen/versi/halaman atau bagian serta mapping yang ditinjau,
bukan sekadar kata 'disetujui'. Format teknis tidak menilai keaslian sitasi/otoritas
klinis. Evidence berada hanya di RAM browser; POST hanya existing publication
fields, bukan endpoint/mekanisme kedua. Arsipkan paket/matriks lengkap di catatan
persetujuan eksternal karena backend menyimpan ref/aktor/waktu/definisi, bukan
sitasi lokal. Jangan mengisi data pasien ke paket.

GET history tetap immutable raw JSON dengan generated option IDs/labels; input
machine-value mapping tidak dikirim balik endpoint ini. Cocokkan mapping dengan
arsip approval, bukan menebak value dari ID. Tidak ada tombol republish dari JSON
server. Tidak ada upload/penyimpanan browser atau seed aktif.

## Konkurensi, kegagalan, expiry

Review menangkap expected_current_version, GET ulang sebelum POST dan menolak
perubahan; server kembali memeriksa di transaksi existing. Mengedit field membatalkan
review/centang. POST dijaga single-flight; tutup biasa diblokir saat pending,
logout tetap tersedia dan menghapus UI sesi. Token/response dari layar lama tidak
memulihkan dialog. Timeout30detik/response mismatch/putus koneksi sesudah POST
mengunci pengiriman ulang; cek seluruh halaman daftar, versi/aktor/waktu/ref.
Tidak ada klaim pembatalan server atau bahwa versi yang ditemukan pasti dari
request terakhir.409/422 memerlukan review baru, tanpa auto retry.401/403 menutup
akses sesuai existing auth. Receipt sukses harus cocok versi/ref/effective/expiry
beserta actor/time valid. Future/expired/invalid stored version tidak disebut aktif.

Android tetap memuat API status, memulai VAS tanpa nilai, menampilkan question/option
ID sesuai publikasi, mengirim vas_mm integer dan provenance versi, bukan menghitung
warna. Entri sukses dibaca dashboard existing dengan linked historical labels;
perubahan versi tidak mengganti kata-kata sejarah. Expiry tidak menghilangkan exact
UUID receipt, tetapi menolak pengiriman baru. Tidak ada SOP klinis/FCM/WhatsApp aktif.

## UAT tanpa mengubah data existing

1. Gunakan schema baru disposable *_test, APP_ENV=testing; jangan gunakan telenapas_demo.
2. Login role tidak berwenang: API GET/POST403/401 dan editor tidak terbuka.
3. Login peneliti sah, buka review kosong: status menunggu, tidak ada POST/row baru.
4. Paket tidak lengkap/citation kosong/nyeri dada belum disepakati: jangan publish.
5. Hanya dalam pengujian terisolasi gunakan paket SYNTHETIC test-only. Review nilai,
   sumber, VAS terpisah, jadwal, WIB calendar conversion, ref sintetis berlabel test.
6. Centang dan klik satu kali. Uji double click, expired token, concurrent version409,
   validation422,500/timeout, response hilang serta logout saat pending. Tidak ada
   auto POST/false success; audit immutable dan approval server tetap terjaga.
7. Sebelum effective Android unavailable, sesudahnya valid instrument/requiredanswers;
   VAS0/100; submit → historical staff read. Setelah expiry unavailable dan UUID
   replay tetap memperoleh receipt. Tidak ada classification/alert/notification rows.
8. Pada UAT nyata setelah deployment terpisah yang disetujui, peneliti sendiri
   melakukan konfirmasi publikasi dengan dokumen/keputusan lengkap. PR ini tidak
   melakukan langkah tersebut atau memerlukan reset akun/riwayat demo.

Hasil uji dan limitasi dicatat setelah verifikasi. Konfirmasi penelitian nyata,
APK/device UAT dan hosted review berbeda dari Jest/export; jangan menyebut hasil
sintetis sebagai validasi klinis atau aktivasi database UAT.

## Kompatibilitas ukuran Android

API mengizinkan hingga 50 pertanyaan/20 pilihan, tetapi antrean terenkripsi Android
existing membatasi JSON lengkap menjadi 16 KiB. Dashboard menolak paket yang
estimasi konservatif snapshot + body + receipt + metadata-nya melampaui batas:
ID aman integer maksimum, semua pertanyaan terjawab, pilihan terpanjang, padding
256 karakter dan pengali UTF-8 maksimum tiga per unit UTF-16. Ini batas rekayasa,
bukan batas/skor klinis. Tidak ada pemotongan otomatis. Jika definisi disetujui
melampaui batas, perlu perubahan kompatibilitas Android yang ditinjau terpisah;
memanggil API langsung tidak memperoleh guard tambahan dashboard ini.
